# tcc for sic

The [Tiny C Compiler](https://repo.or.cz/tinycc.git) ("mob" branch), running on
sic so programs can be written and compiled on the OS itself:

```
/ $ tcc /usr/src/hello.c -o /tmp/hello && /tmp/hello
```

## The port

`patches/` on top of the upstream tree:

- predefine `__sic__` (not `__linux__`), with matching type defaults in `tccdefs.h`
- executables start at `0x8000000000` and carry sic's OS/ABI byte (`0x53`)
- `-static` by default (sic has no dynamic linker); `tcc -v` says sic

`config.h` is generated by the Makefile: tcc looks for its runtime in
`/usr/lib/tcc` (`libtcc1.a`, its own `stdarg.h` & co.) and for the C library in
`/usr/include` and `/usr/lib`, which the port populates from the sysroot (`$SIC_SYSROOT/usr`)
(musl headers, `libc.a`, `crt1.o/crti.o/crtn.o`). Backtrace, bounds checking and
semaphore locking are compiled out. `tcc -run` needs executable anonymous
`mmap`, which the kernel doesn't grant yet.

tcc itself and `libtcc1.a` are cross-compiled with clang like the rest of ZAE;
only the tiny `c2str` helper (which turns `tccdefs.h` into C strings) runs on
the host.
